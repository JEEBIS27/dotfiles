# Tide Island

Jeebis Island is the desktop shell maintained in `vendor/jeebis-tide-shell/`, originally based on Tide Island 1.0.49. Qt/C++ backends, Quickshell and runtime tools are declared in `packages/tide-island.nix`.

## Lifecycle

- `tide-island.service`: island, launcher, notifications, clipboard and session lock.
- `jeebis-wallpaper.service`: mpvpaper for still images, GIF and video.
- `jeebis-idle.service`: swayidle, 600-second idle lock and before-sleep lock.
- `jeebis-display-rotation.service`: independent personal display rotation.

UWSM starts the graphical session services. Do not add another `exec-once` launcher. `jeebis-desktop shell restart` restarts Tide. Log out and back in after migrating; do not keep the previous shell running alongside Tide.

## Managed settings

Open **Jeebis Island 設定** from the Control Center gear or with **Super+Shift+Esc**. **表示時間と操作** edits the two edge handles (2 s), Island auto-hide and peek (2 s), workspace/app/level feedback (1.25 s), notifications and completions (6 s), foreground work (6 s), track changes (5 s), and Bluetooth details (2.5 s). Values are in seconds and take effect in the running shell.

Home Manager seeds missing preferences from `files/desktop/tide-preferences.json`. Later activations update untouched defaults and retain local edits. Wallpaper integration commands and paths are always supplied by the desktop. Use `just tide-import` to share reviewed preferences through Git.

Credentials, clipboard history, calendar notes and caches remain local. Wallpaper commands and store paths are generated by Nix rather than imported. Activation saves the previous configuration as `~/.config/tide-island/userconfig.before-home-manager.json` when values change; this backup is local and replaced on subsequent changes.

The temporary reveal uses the configured Island auto-hide delay. Pressing the
shortcut again restarts the timer. Expiry leaves the normal visibility state intact.

Control Center and the power menu support `Tab`/`Shift+Tab`, arrows and
`H/A/O/E` (Graphite); activate the focused item with `Enter` or `Space`. Press `F` to show
Vimium-style action hints. The hints are never shown merely by opening a panel.
In the power menu, wallpaper picker, File Shelf and clipboard image preview,
Up selects the item on the left and Down selects the item on the right.
The same rule applies to Graphite O/A and to I/K with Ctrl, Alt or Super when
the key reaches Tide. Typing in the wallpaper search box edits the query.
Restart and power-off actions use a confirmation step.

## Theme and wallpaper

Use [the theme tool](theme-tooling.md) for fixed palette + home wallpaper + lock wallpaper presets. Tide's color tokens read the generated `jeebis-theme/current/tide-colors.json`; the lock screen reads the generated static lock wallpaper. The implementation lives in `vendor/jeebis-tide-shell/`. Theme changes do not restart the shell or its password conversation.

The wallpaper picker invokes `jeebis-desktop wallpaper set`; mpvpaper owns rendering independently of the shell. Video/GIF home wallpaper requires a static `lockWallpaper` in the preset. The picker changes the home wallpaper only; choosing a theme preset restores that preset's pair.

## Previous shell

The current shell source lives in `vendor/jeebis-tide-shell/`. It incorporates
the existing changes to Tide Island 1.0.49 and builds directly from that tree.
The existing Nix package, service and configuration names remain available.
When the workspace changes, the central Island briefly shows an accent pill
for the active workspace and filled dots for other occupied workspaces. The
capsule fits the visible indicators, and a spinner marks sustained CPU use by
window processes.
The first or last window of an application on the active Niri workspace briefly
shows its app icon queue. The icon joins or leaves the row with an animation.

The previous Hyprland shell is archived in [JEEBIS27/jeebis-shell](https://github.com/JEEBIS27/jeebis-shell).
Compatibility command adapters and Hyprland defaults do not require an
installed Omarchy OS on NixOS.

This migration has not been built or tested on the destination PC. Login, PAM unlock, clipboard, notifications, theme changes, video playback and suspend require destination testing.


## Native notification endpoint

On Niri, Home Manager starts `mako.service` as the receiver for
`org.freedesktop.Notifications`. Tide observes notification calls and renders the
popup/history; mako handles protocol replies with its own popups hidden to avoid
duplicates. Without this endpoint, tools such as fish's `done` plugin print
`Failed to show notification ... ServiceUnknown`. The service follows the graphical
session and restarts on failure.

## Wi-Fi authentication

Tide's NetworkManager backend delegates connections to `jeebis-tide-wifi`,
using libnm and libnma's standard Wi-Fi authentication dialog. The actual AP and
Wi-Fi device capabilities determine the available security methods. Compatible
saved profiles are selected with libnm; an SSID match alone does not select a
profile. In particular, an old Personal/PSK profile is not reused for an
Enterprise/802.1X AP with the same SSID. Valid saved profiles connect directly.
New profiles autoconnect and are restricted to the current user.

The previous backend discarded WPA/RSN authentication flags and assigned
`wpa-psk` to every encrypted network. `packages/desktop/tide-wifi.patch` removes
that connection builder and bypasses the panel's password-only prompt on
NetworkManager. The iwd backend retains its existing provisioning behavior.

Enterprise detection does not reveal the institution's EAP method, identity,
CA/server validation requirements or client certificate. Enter these using the
institution's instructions in the standard dialog; no PEAP/TTLS/TLS choice or
certificate-validation bypass is guessed. Credentials remain in NetworkManager
or its configured secret storage, never in the repository or process arguments.

`python3 scripts/check-tide-wifi.py` exercises real libnm/libnma against an
isolated mock NetworkManager and never modifies the real connection. Its Python
requires PyGObject, dbus-python and python-dbusmock, with Gtk/NM/NMA typelibs.
The packaged helper exposes the same suite as `tests.authentication` in
`packages/tide-wifi.nix`, using Xvfb in a Nix build sandbox. Tests cover the
Enterprise, Personal, WPA3, Enhanced Open and open dialogs, plus rejection of an
incompatible saved PSK profile. The patched Niri Tide package was built and its
shell started successfully on the Laptop. Authentication against the university
AP has not been tested here.

A targeted user-service deployment can use
`~/.config/systemd/user/tide-island.service.d/90-jeebis-wifi-deployment.conf`,
with a GC root at `~/.local/state/jeebis-desktop/tide-wifi-deployment`.
This survives logout/reboot. Home Manager removes both only when the managed
unit points to its current Tide package and that package has the
`network-auth-version` marker. An activation using an older Tide package must
not remove a tested live fix.

`jeebis-network-agent.service` runs the standard NetworkManager applet/secret
agent on native NixOS sessions. It handles initial authentication, requests for
new passwords after an EAP failure and agent-owned credentials. Tide's connection
helper alone cannot answer NetworkManager's later GetSecrets requests. The agent
may also appear in the system tray; Tide remains the Wi-Fi selection panel.
The university connection logs on 2026-11-17 showed `No agents were available`
after an association timeout; adding the agent fixes the missing prompt, not
proof that the saved institution-specific EAP settings are correct.

`python3 scripts/check-tide-deployment.py` tests stale-package, stale-unit and
updated-unit activation cases. Targeted installation of the authentication
agent also keeps a GC root at
`~/.local/state/jeebis-desktop/network-agent-deployment`; the managed activation
releases it together with the Tide deployment pin.

### EAP method negotiation

For password profiles using inner MSCHAPv2, Tide offers compatible PEAP and TTLS
methods together with the already configured tunneled method. NetworkManager /
wpa_supplicant can then accept the server's EAP request instead of rejecting
PEAP because a saved profile happened to specify FAST. This applies to saved and
new profiles and does not depend on the SSID. The updated EAP list is persisted
so NetworkManager's subsequent automatic connections use it too.

PAC-bound FAST, client-certificate/private-key profiles, EAP-TLS, other inner
methods and non-tunneled EAP profiles retain their explicit configuration.
FAST is never newly enabled. No identities, passwords, CA/server validation,
TLS policy or inner authentication settings are changed. A server request can
select among compatible configured methods; it cannot supply missing account
credentials, client certificates or an institution's CA trust configuration.

The isolated suite includes five additional negotiation tests: FAST-to-PEAP,
PEAP/TTLS negotiation and idempotence, and preservation of certificate auth,
PAP-only inner auth and PAC-bound FAST. It also compares all non-EAP properties,
including credentials and trust settings, before and after negotiation.
## Desktop activities

The clock opens the calendar. Click or pull down the handle at the top left for Notification Center and the handle at the top right for Control Center. Both panels sit 4 logical pixels from the top and side, with a 4-pixel outline matching the Niri focus ring. The corner margin accepts clicks while its panel is open. On Niri, Super+N opens Notification Center and Super+Space opens Control Center. The Control Center drawer contains Silent, Night, Awake, Timer, Capture, Record, Audio out and Display out. Awake uses the Wayland idle inhibitor. Display out moves the active window to the chosen connected monitor and focuses that output. Audio out also moves existing playback streams to the selected sink. Battery percentage and brightness appear when their system devices report a measurement.

An unanswered question takes the main capsule. App notifications, completions, track changes and AI work transitions appear briefly. Ongoing transfers, timers and recordings can occupy the main capsule, followed by continuous music. Routine AI work moves to the small capsule after six seconds, leaving the clock visible when there are no other activities. Click the body to expand the details and focus or launch the source app. Click the chevron or the small capsule to inspect the activity. Notification buttons call the action supplied by the sender. The left panel keeps recent notifications and completions for the current shell session.

Recording opens the Wayland screen chooser and saves through Qt Multimedia. On Niri the GNOME screen-cast portal uses the session's Fcitx module from GIO. Its service override removes the additional GTK search path that would load a second copy and abort the chooser.

Tide listens for freedesktop notifications and their progress hints, Unity LauncherEntry progress and Herdr's reported agent status. Producers can also publish a job directly. Reuse its ID through completion and supply a desktop entry or compositor window ID to identify the source.

```sh
tide-activity working --id build-17 --app Editor --desktop org.gnome.TextEditor --title "Building"
tide-activity progress --id build-17 --app Editor --desktop org.gnome.TextEditor --title "Installing" --value 48
tide-activity done --id build-17 --app Editor --desktop org.gnome.TextEditor --title "Installation complete"
tide-activity ask --app Editor --desktop org.gnome.TextEditor --title "Review the change" --body "What should change?" --choice "Keep it"
```

The question card follows the ChatGPT option picker. Select a suggestion, type a free response, or add a note to a selection. Submit or Ctrl+Enter sends the answer. Enter inserts a newline. Collapsing the card keeps its draft while the question is pending. The caller receives plain text for a single answer. A selection with a note returns JSON with `option` and `answer`. Skip returns `{"type":"skipped"}`. Closing the requesting process withdraws its question. The socket lives in the user's runtime directory.

Home Manager adds the `tide_island` MCP server and lifecycle hooks to the local Codex configuration. In a new Codex session the `ask_user` tool accepts a question and optional choices, and returns the user's answer. Review new command hooks in Codex's hook review UI. Hooks report work, elapsed time, and completion. The `PermissionRequest` hook runs before approval is resolved. Codex shows its own permission dialogs, and Tide shows `Needs you` for actual questions sent through its tool. [Codex hooks](https://learn.chatgpt.com/docs/hooks#permissionrequest)

Run `python3 scripts/check-tide-activities.py /path/to/tide-activity` to test the producer, reply transport and Codex configuration merge using a private runtime directory.
