# UI design and review

For every UI task, read the applicable project DESIGN.md before changing the interface. Follow the user's requirements and the project's design decisions when a skill suggests a conflicting direction.

1. Use impeccable as the primary skill for designing and refining layouts, hierarchy, spacing, typography, color, and information architecture. Ground decisions in the user's task and the existing interface.
2. Once the structure works, use emil-design-eng where press, hover, focus, motion or transitions need attention.
3. Use web-design-guidelines for the final audit of web interfaces. For native interfaces apply the relevant principles using native controls and accessibility semantics.
4. Preserve existing functionality and keyboard access. Check focus visibility, forms, navigation, contrast, and supported window sizes. Exercise the actual UI and inspect screenshots when feasible. Fix problems found and verify again.
5. Record reusable project decisions in DESIGN.md. Select skills according to the work; a small change can use a subset of this workflow.
